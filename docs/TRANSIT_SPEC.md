# Pontifex Planetary Transit Specification

## Overview

The Pontifex Planetary Transit Fabric is an autonomous, multi-region software-defined backbone network modeled entirely in declarative HCL. It implements deterministic supernet allocation, route reflector BGP topologies, anycast virtual IP (VIP) edge injection, and high-availability egress NAT gateways across arbitrary continental regions.

## 1. Deterministic Supernet Allocation

The transit fabric partitions a designated IPv4 supernet (default `10.0.0.0/8`) across operational regions using deterministic `cidrsubnet` calculations.

### Allocation Formula

For a supernet with prefix length $S_{len}$ and regional allocation offset $R_{len} = 16$:

$$\text{Regional CIDR}_i = \text{cidrsubnet}(\text{Supernet}, R_{len} - S_{len}, i)$$

Where:
* $i$ is the zero-based index of the region in the lexicographically sorted region key list.
* Within each regional `/16`, subnets are further sliced for:
  * Public ingress: `/20` (4,096 addresses)
  * Private workload mesh: `/18` (16,384 addresses)
  * Data plane storage: `/20` (4,096 addresses)
  * Cross-region transit peering: `/20` (4,096 addresses)

### Peer Link Addressing

Point-to-point cross-region links are carved out of the transit peering allocation using `/30` subnets:

$$\text{Link CIDR}_{i, j} = \text{cidrsubnet}(\text{TransitPeeringCIDR}, 30 - 20, k)$$

Each `/30` provides exactly two usable host IPs:
* `.1` assigned to Region $i$
* `.2` assigned to Region $j$

This mathematical guarantee eliminates CIDR overlap across regions without central IPAM coordination services.

## 2. BGP Route Reflector Mesh

To scale BGP peering across $N$ planetary regions without requiring $O(N^2)$ full iBGP meshing, Pontifex implements a dual route-reflector cluster architecture.

### Autonomous System Numbering (ASN)

* **Route Reflector Cluster ASN**: Designated 16-bit or 32-bit private ASNs in the RFC 6996 range (`64512` to `65534`).
* **Regional Node ASNs**: Unique per-region private ASN offsets calculated as:

$$\text{ASN}_{\text{region}} = \text{BaseASN} + i$$

### Peering Attributes & Policy Controls

Every BGP session generated by `modules/transit_fabric/bgp_mesh.tf` enforces the following attributes:

1. **Keepalive and Hold Timers**:
   * Keepalive: 10 seconds
   * Hold Time: 30 seconds (3 missed keepalives trigger fast path failover)
2. **MD5 Authentication**:
   * Cryptographically secure session authentication tokens derived from the cryptographic seed.
3. **Route Metrics**:
   * **Multi-Exit Discriminator (MED)**: Set dynamically based on inter-continental latency matrices.
   * **Local Preference**: Ingress preference values favoring local transit breakout (default `100`, edge overrides up to `200`).
   * **AS-Path Prepending**: Configurable prepend steps for secondary path deprioritization during simulated failovers.

## 3. Anycast Edge VIP Injection

Pontifex exposes global services through Anycast Virtual IPs (VIPs) announced concurrently from every edge point of presence.

### Traffic Steering Mechanism

* Edge routers announce identical `/32` (IPv4) or `/128` (IPv6) host routes into upstream Tier-1 internet carriers.
* Ingress traffic is steered by internet transit providers via BGP Equal-Cost Multi-Path (ECMP) and shortest AS-Path distance to the nearest physical PoP.
* In the event of catastrophic PoP failure, BGP withdraws the VIP advertisement within 30 seconds, seamlessly rerouting downstream packets to the next closest healthy region.

### Geo-Proximity Fallback Matrix

Each regional deployment maintains a coordinate vector:

$$\vec{P}_{\text{region}} = (\text{Latitude}, \text{Longitude})$$

Haversine distance calculations are computed in policy modules to determine nearest-neighbor backup routes if local capacity saturation triggers circuit breaking.

---

## 4. High-Availability Egress NAT Topology

Egress traffic to third-party endpoints, external registries, and non-mesh resources passes through multi-AZ redundant NAT gateways.

### Configuration Characteristics

* Distributed across all availability zones in the regional VPC.
* Independent static Elastic IP allocations per zone.
* Default egress route tables configured per private subnet directing `0.0.0.0/0` to the corresponding zonal NAT gateway.
* Automatic zone-level isolation: a failure in AZ-a does not impact egress flows originating in AZ-b or AZ-c.
